# Local first-token experiment

Run serve_benchmark.py with an absolute llama-server binary path and a GGUF path. The run used official llama.cpp build b12668 for macOS arm64 and ggml-org/models at revision 499bc8821c6b12b4e53c5bffcb21ec206f212d81, file tinyllamas/stories15M-q4_0.gguf (SHA-256 66967fbece6dbe97886593fdbb73589584927e29119ec31f08090732d1861739).

Each of four separate processes serves one active request, CPU only, one inference thread, with eight generated tokens per request. The client dispatches through a separate FIFO executor per replica. Time is measured from burst submission to first nonempty streamed text, including client-side queueing, HTTP and prompt processing. Queue time ends at the beginning of dispatch. It excludes server-side wait. Quantiles are nearest-rank over requests, not over independent machines.

Each burst starts with one deliberately primed prompt family per worker. Nine requests share one family and the other three have different families. The popular family rotates. Requests have minor suffix changes. Round robin assigns by request position. Fixed prefix affinity sends each request to its primed worker, an intentionally simple policy with no queue penalty. There are 12 deterministic bursts per trial, two trials per policy, in round-robin / affinity / affinity / round-robin order. Priming calls are excluded. This is a controlled serving test with synthetic text; it does not run the anonymized Mooncake requests or reproduce a production dynamic prefix router. No extrapolation to continuous GPU batching or production latency.
